# Art spec

All game art lives in `Assets/Resources/Art/`. The game loads it by file name at runtime, so to use
your own art you **overwrite a placeholder PNG with yours, keeping the same name and layout**. No code
or Unity setup is needed: import settings (point filtering, no compression, no resizing) are applied
automatically by `Assets/Editor/ArtImporter.cs`.

The placeholders are generated by `Tools/placeholder_art/generate.py`. Don't re-run it after adding
your own art, because it overwrites every file in `Art/`. You can also run a single part, e.g.
`Tools/.venv/bin/python Tools/placeholder_art/generate.py tiles`.

## Global rules

| Rule | Value |
|---|---|
| Pixels per unit | **64** (one ground tile is 64 px wide = 1 world unit) |
| Projection | 2:1 isometric: tile diamonds are 64×32, camera elevation ≈ 30° |
| Light direction | from the **upper left, slightly toward the viewer** (keep shading consistent with the placeholders) |
| Format | PNG, RGBA, transparent background, no anti-aliased edges against transparency |
| Scaling | The camera shows art at an integer zoom (2× at 720p, 3× at 1080p, 4× at 1440p) |

## Characters: `Art/Characters/<name>/`

One folder per character (`warrior`, `bandit`, `elder`, `merchant`, `guard`, `nomad`, `hunter`,
`wolf`, `frost_wolf`, `scorpion`). Each folder has one PNG per animation, plus `character.json`.

**Sheet layout:** columns are frames (left to right) and rows are directions (top to bottom):

| Row | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| Facing | **S** (toward viewer) | SW | W | NW | N (away) | NE | E | SE |

- **8 rows** is the full set. You can also supply **5 rows** (S, SW, W, NW, N); the game mirrors them
  for NE, E and SE. Or supply **1 row** (a side view facing east), which is mirrored for west. The game detects
  this from the image height.
- "S" means facing **down the screen**, toward the camera. W is screen-left, N is screen-up.

**Frame:** 64×64 px. The **feet** go at pixel **(32, 10) measured from the bottom-left** of each
frame. That is the pivot, and it is used for depth sorting and collisions. A human is about 40 px tall.

**Animations** (used by the code):

| File | Frames | FPS | Loop | Notes |
|---|---|---|---|---|
| `idle.png` | 4 | 5 | yes | breathing / standing |
| `walk.png` | 8 | 12 | yes | full stride cycle |
| `attack.png` | 6 | 16 | no | warrior and enemies only. Damage lands on `hitFrame` (3) |

Frame counts, FPS, frame size and pivot can all be changed in `character.json`. The code reads
them from there, so a 10-frame walk or 96×96 frames work without code changes:

```json
{
  "frameWidth": 64, "frameHeight": 64, "pivotX": 32, "pivotY": 10, "ppu": 64,
  "animations": [
    { "name": "idle",   "file": "idle",   "frames": 4, "fps": 5,  "loop": true,  "hitFrame": -1 },
    { "name": "walk",   "file": "walk",   "frames": 8, "fps": 12, "loop": true,  "hitFrame": -1 },
    { "name": "attack", "file": "attack", "frames": 6, "fps": 16, "loop": false, "hitFrame": 3 }
  ]
}
```

## Ground tiles: `Art/Tiles/<name>.png`

- One diamond is **64×32 px**. Put **variants side by side**: a 192×32 PNG has 3 variants, and the
  game picks one per cell.
- The diamond's edge pixels must follow the 2:1 staircase so neighbours interlock with no gaps (copy the
  outline of a placeholder).
- Make each tile **seamless with itself** across all four diamond edges.
- Names used by the maps: `grass`, `grass_flowers`, `forest_floor`, `path`, `water` (not walkable),
  `sand`, `dune`, `cracked_earth`, `snow`, `snow_path`, `ice`. Adding a new name is fine; just
  use it in a region legend.

## Props: `Art/Props/<name>.png` + `props.json`

Trees, rocks, houses and so on. Each is one PNG of any size. `props.json` holds, per prop:

| Field | Meaning |
|---|---|
| `pivotX`, `pivotY` | pixel (from bottom-left) where the prop touches the ground, at the centre of its footprint |
| `colliderType` | `none`, `ellipse` (uses `radius`, in world units) or `diamond` (`halfWidth`/`halfHeight`) |
| `fade` | `true` makes it turn see-through when the player walks behind it (trees, houses) |
| `offsetX`, `offsetY` | in grid cells; the house uses 0.5/0.5 so its 2×2 footprint centres on a cell corner |

## Portraits: `Art/Portraits/<name>.png`

Head-and-shoulders portraits for the dialogue box: **96×96** (any square size works; it's scaled to fit
at the nearest pixel). Names match the `portrait` column in `Resources/Data/npcs.txt`. The player's
portrait is `warrior.png`.

## Checklist for one character

1. Draw `idle`, `walk` and `attack` at 64×64 per frame, 8 rows in the order S, SW, W, NW, N, NE, E, SE.
2. Put the feet at (32, 10) from the bottom-left in every frame.
3. Save them over `Assets/Resources/Art/Characters/warrior/idle.png` (and the others).
4. If your frame counts differ, update `character.json`.
5. Press Play.
